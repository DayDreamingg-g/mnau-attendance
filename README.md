# MNAU Attendance · TEST

Рабочий проект Next.js / React / Prisma / PostgreSQL. Интерфейс — украинский. Релиз 15.09.2026: [результаты и применение](docs/TEST-RELEASE-2026-09.md), [Windows / Docker](docs/WINDOWS.md).

## Данные и обновление

Основной источник — `source-data/cs-beta/Списки груп (2).docx`: 128 строк, КН 1/1 — 17, КН 2/1 — 30, КН 3/1 — 20, КН 3/2 — 21, КН 4/1 — 40. ФИО сохраняются в исходном написании. Новая версия источника связывается с прежними 58 Student через явное соответствие строк; ID, importKey, аккаунт и история остаются. Новые Student не получают login accounts.

Порядок обновления существующего TEST: `db:migrate` → `beta:import-complete-cs-roster -- --dry-run` → `beta:import-complete-cs-roster -- --apply` → `beta:backfill-cs-history -- --dry-run` → `beta:backfill-cs-history -- --apply` → `beta:verify-cs` → web. Полные команды приведены в инструкции релиза. Импорт и backfill выполняются отдельно от запуска web. Проверка различает 128 официальных строк и текущий живой состав; законные добавления, переводы и архивирование допустимы.

`db:seed`, `beta:prepare-cs`, `beta:repair-cs`, `demo:attendance`, `db:reset-demo` заблокированы вне изолированных regression fixtures. Они не входят в обновление. Не запускайте `setup:env` или `beta:realtime` поверх существующей конфигурации. Существующие env, секреты, n8n и volumes сохраняются.

## Семестр и история

Подтверждённый семестр: **01.09.2026–31.12.2026**. Миграция привязывает существующие занятия, сохраняя ID. Прежние январские занятия остаются в БД, вне этого семестра. Праздники и каникулы не заданы источником.

Backfill ограничен 01–14.09.2026, исключает текущий день Europe/Kyiv, незавершённые и отменённые пары, архив и целиком любой вручную затронутый журнал, в том числе очищенный. Seed, алгоритм, параметры, batch и происхождение отметок сохранены. Повтор ничего не меняет. Совместная пара остаётся одной Lesson с двумя группами. Обычный импорт не дописывает прошлые ручные roster.

Семестр закрывают ADMIN/DEVELOPER или деканат своего факультета. Архив защищён от изменений на уровне PostgreSQL, включая технические записи. Новый семестр и состав подтверждает администратор; автоматического перевода студентов по курсам нет.

## Журнал, отчёты и права

Преподаватель и староста используют общие сохранённые отметки. Староста редактирует только свою группу совместной пары. Запись разрешена после начала пары до конца текущего дня; позже — уполномоченным ролям с причиной. Транзакции, аудит, requestId и проверка версии защищают от повторов и тихой перезаписи. Несохранённые изменения остаются в форме при конфликте.

Формула общая: `PRESENT / (PRESENT + N) × 100`. HV и невідмічені исключены. Нулевой знаменатель — «Немає даних». Порог применяется до округления, агрегаты считаются из сумм статусов. Полнота заполнения показана отдельно.

Отчёты: текущая неделя / произвольный период, группы и предметы в доступном scope; сохранённый просмотр, PDF, CSV и XLSX. Основная строка — занятие × группа. Уникальные студенты и student × lesson различаются; исторический состав берётся из LessonStudent. Снимок и файлы хранятся в PostgreSQL и переживают redeploy. PDF содержит украинский шрифт, CSV — UTF-8 BOM и `;`, XLSX — текстовые ячейки без формул из пользовательского ввода. n8n не требуется для ручного отчёта или сохранения посещаемости.

Полный профиль доступен преподавателю, куратору, деканату, ADMIN/DEVELOPER. Староста меняет обязательный пароль на отдельном экране. Первый вход после миграции выданных TEST-аккаунтов требует однократной смены; хеши не заменяются. Сброс выдаёт уникальный временный пароль один раз, отзывает сеансы. Общего reset-пароля больше нет. Настраиваемый cooldown и сеансы хранятся в БД.

Teacher и User связаны по ID; изменение ФИО сохраняет пары и исходное имя. Мастер преподавателя, несколько ролей, назначения и архивирование сохраняют проведённые занятия. Собственные роли меняет только DEVELOPER отдельным действием; последний административный доступ защищён. Рабочее пространство меняет навигацию. Деканат видит справочник пользователей своего факультета без выдачи глобальных ролей.

Feedback доступен всем действующим пользователям, административные вкладки — уполномоченным ролям. Онлайн-ссылку меняет преподаватель своей пары, деканат своего факультета или ADMIN/DEVELOPER. Источники открываются через авторизованный endpoint, глобальный DOCX не доступен преподавателю. Телефоны преподавателям не отправляются. Student accounts и публичная регистрация отложены.
