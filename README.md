# MNAU Attendance

Текущая рабочая версия приложения учёта посещаемости МНАУ. Интерфейс украинский. Обновление продолжает существующий проект `mnau-attendance`, сохраняет его стек, данные и разделение баз приложения и n8n.

**Реализовано:** вход с JavaScript и обычной HTML-формой; серверные сессии; пять совмещаемых ролей с управлением назначениями; факультет → специальность → группа → студент → история → занятие; сортировка и фильтры в URL; общий dropdown; журнал с черновиками, подтверждением и аудитом; защита совместных занятий; светлая/тёмная тема; preview и PDF/CSV-отчёты; шесть workflows n8n.

Проверенные группы взяты из четырёх приложенных PDF. **Все 420 студентов, даты занятий, посещаемость и demo email вымышлены.** Синтетическое занятие с фамилией преподавателя из источника не означает, что этот человек проводил его или выставлял отметки. Это не официальный электронный журнал университета.

## Обновление и запуск: Windows / PowerShell

Нужны Docker Desktop с Linux containers и Node.js `>=22.12.0 <25`; проверка выполнена на 24.19.0. Команды ниже выполняются в текущем проекте, например `E:\Repo\mnau-attendance`. При переносе обновления сохраните существующие `.env`, `.env.compose` и Git metadata. Подробная инструкция с перезапусками и импортом n8n: [docs/WINDOWS.md](docs/WINDOWS.md).

```powershell
Set-Location E:\Repo\mnau-attendance
docker compose --env-file .env.compose build web migrate seed
docker compose --env-file .env.compose up -d postgres
docker compose --env-file .env.compose run --rm migrate
docker compose --env-file .env.compose up -d web n8n
docker compose --env-file .env.compose ps
```

Только при первой установке, когда обоих env-файлов ещё нет, предварительно выполните `npm.cmd run setup:env`. Команда использует встроенные модули Node, создаёт случайные независимые секреты и не печатает их. Существующие env-файлы она не перезаписывает. Для обновления настроенного проекта её запуск не нужен.

Seed и demo attendance запускаются отдельно при необходимости:

```powershell
docker compose --env-file .env.compose run --rm seed
docker compose --env-file .env.compose run --rm migrate npm run demo:attendance
```

Генератор заполняет только отсутствующие отметки синтетических занятий, пропускает будущие и отменённые занятия, сохраняет teacher/starosta marks и пишет AuditLog. Повтор не создаёт дубликаты; при изменении данных увеличивается версия журнала. Для seed и генератора обязательны `APP_ENV=demo` и `DEMO_MODE=true`.

- Сайт: [http://localhost:3000](http://localhost:3000).
- n8n: [http://localhost:5678](http://localhost:5678).
- Проверка приложения и реального SQL-подключения: [http://localhost:3000/api/health](http://localhost:3000/api/health). До миграции ответ 503 ожидаем.

Именованные тома: `mnau-attendance_postgres_data` и `mnau-attendance_n8n_data`. PostgreSQL наружу по умолчанию не опубликован. Все опубликованные порты привязаны к `127.0.0.1`.

Повторный запуск:

```powershell
docker compose --env-file .env.compose up -d
docker compose --env-file .env.compose run --rm migrate
```

Обычный `up`, `restart`, `stop`, `down` без `-v` сохраняет данные. Seed запускается только явной командой. Повторный seed не сбрасывает пароли, назначения существующих аккаунтов, сессии или исправления. Не используйте `down -v` для обычного перезапуска.

Проверка текущей базы и конфликтов:

```powershell
docker compose --env-file .env.compose run --rm migrate npm run db:check
docker compose --env-file .env.compose run --rm migrate npm run check:conflicts
```

## Файлы окружения

| Файл | Кто читает | Назначение |
|---|---|---|
| `.env.compose` | `docker compose --env-file .env.compose` | Пароли двух БД, пароль администратора PG, ключ шифрования n8n, машинный токен, порты и demo-режим |
| `.env` | Next.js, Prisma config, seed и локальные Node scripts | Локальное подключение приложения, origin, cookie, demo-дата, машинный токен |
| `.env*.example` | Человек / `setup:env` | Только заполнители, безопасны для Git |

Compose передаёт приложению `DATABASE_URL` с пользователем `attendance_app`, базой `mnau_attendance`, схемой `public`. n8n использует `n8n_app`, `mnau_n8n`, `public`. PostgreSQL init script создаёт обе базы и закрывает PUBLIC CONNECT; каждый прикладной пользователь имеет права только на собственную базу. Миграции Prisma не содержат таблиц n8n.

Docker не копирует `.env` в image (`.dockerignore`). Build использует заведомо фиктивный URL, не обращаясь к БД. Runtime URL приходит из Compose. Секреты не используются в `NEXT_PUBLIC_*`, UI, экспортированных workflow или Git. Ключ `N8N_ENCRYPTION_KEY` нельзя менять при обычном перезапуске: он нужен для расшифровки сохранённых credentials.

Менять порты можно в `.env.compose`: `WEB_PORT`, `N8N_PORT`, `PG_LOCAL_PORT`. При изменении порта сайта измените также `APP_ORIGIN`, а для локального запуска — `.env`.

## Demo-аккаунты и первый сценарий

Пароль всех изначально созданных demo-аккаунтов: `Test1234!`. Создание разрешено только при `APP_ENV=demo` и `DEMO_MODE=true`.

| Email | Роль / назначение |
|---|---|
| `admin@test.com` | ADMIN, вся система и назначения |
| `dean@test.com` | DEAN_OFFICE, только «Факультет менеджменту» |
| `curator@test.com` | CURATOR, группа Кн 2/1 |
| `starosta@test.com` | STAROSTA, студент группы Кн 2/1 |
| `teacher@test.com` | TEACHER, Пархоменко О.Ю.; его собственные занятия |
| `teacher-NN@test.com` | Отдельные преподаватели; точная карта в `docs/demo-accounts.json` |

Второй аккаунт для совмещения ролей не требуется. В «Адміністрування» администратор добавляет и снимает роли, привязки профилей преподавателя/старосты, группы куратора и факультеты деканата. Роль и назначение управляются отдельно; для доступа нужны оба. ADMIN имеет системную область, отдельной ограниченной факультетом роли администратора нет. Снятие привязки не удаляет User, Student, Teacher или историю. Изменения требуют причины и сохраняются в аудите; собственную роль ADMIN снять нельзя. Реальных телефонов в demo нет.

Следующий сценарий рассчитан на чистый seed с ещё незаполненным занятием демо-дня. В существующей базе после генератора уже подтверждённые строки старосте недоступны: выберите разрешённые незаполненные строки или просмотрите подтверждённую историю.

1. Войти как `starosta@test.com`, открыть «Моя група» и занятие за **07.09.2026**. Выбрать `• / N / HV`, сохранить черновик.
2. Выйти и войти как `teacher@test.com`. В «Мої заняття» выбрать ту же дату. Открыть занятие Кн 2/1: черновик уже загружен из БД.
3. «Позначити всіх присутніми» меняет только форму. Скорректировать отсутствующих, нажать «Зберегти», затем подтвердить запись. Успех появляется только после ответа сервера.
4. Обновить страницу. Изменения остаются, есть автор/время/статусы в истории исправлений. Подтверждённые значения староста больше не изменяет.
5. Войти как деканат, выбрать 2 курс и нужный период. Перейти в Кн 2/1 → студента → запись истории → конкретную пару. В «Звіти» выбрать область и период, проверить preview, затем подтвердить создание PDF/CSV.
6. Подключить workflows n8n по инструкции `n8n/README.md` и выполнить их вручную. Созданные отчёты появятся в том же разделе.

**Часы:** фиксированное время включается только вместе с `APP_ENV=demo`, `DEMO_MODE=true` и корректной `DEMO_DATE` формата `YYYY-MM-DD`. Тогда используется 21:00 указанного дня Europe/Kyiv, в UI написано «Фіксований демо-час». Пустая `DEMO_DATE` оставляет настоящее время даже в demo; подпись меняется на «Реальний час». Для production нужны `APP_ENV=production`, отключённый `DEMO_MODE`, пустая `DEMO_DATE` и HTTPS. Некорректная production/demo-конфигурация отклоняется. `NODE_ENV=production` обозначает оптимизированную сборку, поэтому сам по себе не запрещает локальную демку. Сессии и login rate limit всегда используют реальные часы. Изменение demo-даты не переносит существующие занятия и не перезаписывает историю.

## Навигация, таблицы и журнал

Дата и фильтры сохраняются при drill-down и возврате: факультет → специальность → группа → студент → история посещения → занятие. История показывает дату, пару и время, предмет, преподавателя, группу, корпус/аудиторию, статус и подтверждение. Доступ к каждому переходу заново проверяет сервер.

Заголовки таблиц студентов, групп, специальностей, отчётов, посещений и подходящих колонок аудита переключают `asc/desc`; URL хранит `sort/order`, текущие фильтры и порог 50/70. Текст сравнивается через украинскую локаль, числа и даты по значению. `null` всегда в конце, равные значения сохраняют исходный порядок. Сортировка сохранённых отчётов относится к последним 100 записям, аудита занятия к последним 200; пределы указаны в UI.

Общий `CustomSelect` используется в фильтрах и формах. После hydration доступны стрелки, Home/End, поиск вводом, Enter, Escape, Tab, выбранный/заблокированный вариант и прокрутка. Внешний клик закрывает список. Реальный form control сохраняет GET-параметры и работает до hydration; оформление учитывает текущую тему.

В журнале доступны кнопки PRESENT/N/HV/«Не відмічено», а в сфокусированной строке клавиши `1/2/3/0`. Массовая отметка меняет только локальный черновик. Перед отправкой показано подтверждение; при ошибке черновик остаётся, при конфликте 409 можно загрузить актуальные данные. Успех и доступность строк берутся из ответа сервера. Двойная отправка блокируется; повтор того же запроса не дублирует аудит.

## Формула и доступ

Единая функция `src/lib/metrics.ts`:

`PRESENT / (PRESENT + N) × 100`.

HV исключён из знаменателя и виден отдельно. 4 PRESENT + 1 N + 1 HV → **80%**; фактическая доля присутствия среди всех отметок — отдельные **66,7%**. Если PRESENT+N=0, результат `null` / «Немає даних». Такие студенты не входят в пороги. Порог `<70%` включает критические `<50%`; сравнение до округления. Агрегаты суммируют исходные количества.

Считаются только подтверждённые записи завершённых неотменённых занятий в периоде. Черновики, отсутствующие записи, будущие пары и отмена различаются. Полнота журнала считается отдельно: подтверждённые отметки / ожидаемые отметки завершённых занятий. Число занятий определяется по Lesson, а не по максимуму отметок студента.

Все защищённые страницы и API заново проверяют сессию, роль и область доступа. Cookie содержит случайный непрозрачный токен, в БД только SHA-256; срок 30 дней, HttpOnly/SameSite=Lax, Secure при HTTPS. Logout отзывает именно текущую сессию. Login принимает JSON и `application/x-www-form-urlencoded`/multipart-форму: без JavaScript успешный POST возвращает 303, ошибки отображаются на `/login` без email/пароля в URL. Неизвестный email и неверный пароль дают одинаковую ошибку; Origin и rate limit проверяются в обоих вариантах.

Учитель получает собственные занятия; куратор свои группы; деканат назначенные факультеты; староста собственную группу и разрешённые занятия. Для совмещённых ролей сервер связывает разрешение на занятие и группу в одной ветке проверки: две независимые области не дают доступ к чужим строкам общей пары. Пустые назначения не расширяют доступ. При записи назначение проверяется повторно внутри транзакции.

Для общей пары Кн 3/1 + Кн 3/2 подтверждение относится к каждой Attendance. Состояние Lesson становится CONFIRMED только когда весь ожидаемый roster всех групп заполнен подтверждёнными отметками. Пока часть строк отсутствует или остаётся черновиком, состояние DRAFT; отсутствие всех отметок означает EMPTY. Подтверждение Кн 3/1 не блокирует незаполненные строки Кн 3/2. Староста не меняет уже подтверждённую строку. Миграция `202609060002_complete_roster_journal_state` исправляет старые агрегатные состояния, повышает версии изменённых журналов и добавляет аудит, сохраняя отметки и provenance. Prisma schema и исходная миграция не менялись.

Изменения после дня занятия по Kyiv разрешены только назначенному куратору, деканату или admin с причиной. Не пишите медицинские диагнозы в причину HV. Версия Lesson защищает от двух редакторов; `requestId` защищает от повторного сохранения. Attendance и AuditLog записываются одной транзакцией. Кнопка массового заполнения не отправляет данные сама. При потере сети черновик сохраняется в состоянии формы, но не переживает закрытие вкладки; есть предупреждение о несохранённом.

## Отчёты и n8n

ADMIN и деканат формируют daily, weekly и monthly отчёты по факультету, специальности, группе или студенту. Daily по умолчанию использует текущий день, weekly предыдущую календарную неделю, monthly предыдущий календарный месяц; период можно выбрать явно. Перед созданием видны область, сводные показатели и preview строк. Сохранённый отчёт открывается отдельной страницей с PDF/CSV и прежними фильтрами. Чужой факультет или несовместимые specialty/group/student отклоняются сервером.

Уникальный ключ включает вид, период и область. Неизменённый повтор использует готовый результат; изменение исходных данных обновляет ту же запись. Fingerprint учитывает экспортируемые значения и действующие назначения кураторов. PENDING защищает от параллельной генерации; незавершённую попытку можно повторить после пяти минут. Ошибка формирования сохраняет FAILED, скачивание неполного результата недоступно.

В `n8n/` находятся шесть неактивных импортируемых exports: ежедневная сводка, недельная сводка назначенных кураторов, alerts ниже 70% и 50%, месячная аттестация и ручная оркестрация PDF/CSV. Токен хранится в Header Auth credential n8n, а не в JSON. Машинный API ограничен `REPORT_FACULTY_SLUG`; requests имеют retries, результат проверяется на READY, неуспех остаётся в execution history. Алерты и ссылки сохраняются внутри приложения; внешние сообщения не отправляются. Подробности и точные имена файлов: [n8n/README.md](n8n/README.md).

Недельная автоматизация создаёт один отчёт на реально назначенную группу и сохраняет имена действующих кураторов. Просмотр и скачивание отчётов сохраняют права ADMIN/DEAN_OFFICE; отдельный личный inbox куратора не добавлялся. Расписания n8n используют реальные часы Europe/Kyiv, demo clock сайта не меняет расписание n8n.

## Данные и источники

Из БД на чистом seed: **2 факультета, 28 групп целевого факультета, 420 студентов, 53 отдельных преподавательских записи, 112 дисциплин, 288 синтетических занятий, 2604 отметки, 411 записей источников**. Числа выводятся SQL-запросами после seed, не подогнаны к 600 студентам. Дополнительный факультет имеет отдельную структуру и не наполнен студентами.

В `source-data/` сохранены копии PDF, геометрические координаты ячеек, исходные фрагменты, страница, исходное имя файла и список неоднозначностей. `docs/SOURCES.md` описывает метод и границы подтверждения. Страница «Джерела даних» позволяет проверить записи. Подгруппы/чередование и спорные ячейки не превращаются в официальные даты. Код специальности для конкретного набора не угадывается; поле остаётся пустым при отсутствии подтверждённого соответствия.

## Локальная разработка без web-контейнера

```powershell
Set-Location E:\Repo\mnau-attendance
npm.cmd ci
docker compose --env-file .env.compose -f compose.yaml -f compose.local-db.yaml up -d postgres
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run db:seed
npm.cmd run db:check
npm.cmd run dev:local
```

Override публикует PostgreSQL на `127.0.0.1:${PG_LOCAL_PORT}`: example-файл задаёт 5432, fallback самого override при отсутствии переменной 5433. `DATABASE_URL` в локальном `.env` должен содержать тот же порт. `dev:local` запускает Next на 3000. Не запускайте одновременно локальный Next и web-контейнер на одном порту. Если n8n работает в Docker, а сайт локально, URL HTTP node: `http://host.docker.internal:3000/api/machine/reports`; для полного Compose оставьте `http://web:3000/api/machine/reports`.

Стенд задаёт собственные demo-параметры и временный машинный токен, не использует рабочее подключение из `.env`. Нужны свободные локальные порты 3001 и 5543.

Чистый `npm ci` с install scripts выполнен в отдельном пустом каталоге: установлены 534 пакета, версии совпали с lockfile, lockfile не изменился. Точные результаты тестов и ограничения: [docs/VERIFICATION.md](docs/VERIFICATION.md). Отдельная разрушительная команда `db:reset-demo` требует интерактивного терминала, буквального подтверждения `RESET MNAU ATTENDANCE`, demo-режима и фактического имени БД `mnau_attendance`. В production она заблокирована. Это не часть обычной установки или обновления.

Prisma v7 использует `prisma.config.ts`, генератор `prisma-client` в `src/generated/prisma` и PostgreSQL adapter с одной схемой public.

- `prisma/` — связи, ограничения, миграция и недеструктивный seed.
- `src/lib/` — auth, scope, транзакции, математика, analytics и отчёты.
- `src/app/` — защищённые server pages и API; `src/components/` — общие UI-компоненты.
- `docker/`, `compose*.yaml`, `Dockerfile` — изолированное окружение.
- `n8n/` — шесть импортируемых workflows без secrets.
- `tests/`, `scripts/` — проверки и подготовка.
- `docs/` — источники, аудит, фактические результаты и English commit descriptions.

Технические ориентиры: [Next authentication](https://nextjs.org/docs/app/guides/authentication), [Next proxy](https://nextjs.org/docs/app/getting-started/proxy), [Prisma v7](https://www.prisma.io/docs/orm/more/upgrade-guides/upgrading-versions/upgrading-to-prisma-7), [Tailwind dark mode](https://tailwindcss.com/docs/dark-mode), [n8n Docker](https://docs.n8n.io/hosting/installation/docker/).

## Границы готовности

Серверные проверки выполнены в изолированном стенде. Docker binary/daemon в среде подготовки отсутствует: Docker build, native PostgreSQL/n8n containers, межбазовые права и restart/volumes здесь не проверены. Для них подготовлены команды в [docs/WINDOWS.md](docs/WINDOWS.md). Полная приёмка обновления включает запуск этих команд на рабочем компьютере.

Браузерная среда отклонила открытие приложения/компонентного preview с `ERR_BLOCKED_BY_CLIENT`. Desktop/mobile, визуальная проверка обеих тем и клавиатурное взаимодействие поэтому не считаются выполненными в этом обновлении. Реальная отправка HTML login без JavaScript проверяется HTTP integration test; это отдельная проверка от визуального браузерного сценария.

Исторические результаты аудита зависимостей находятся в `docs/DEPENDENCIES.md`; они не являются свежим security scan этого обновления. Публичный production deployment, нагрузочные испытания и аудит Docker images не выполнялись. Для production предусмотрены HTTPS, Secure cookie и запрет demo clock.

Полная реконструкция официального расписания с чётностью недель и образовательными программами по наборам требует устранения неоднозначностей источника. Сейчас подтверждены заголовки групп и геометрически привязанные записи; календарь явно синтетический. Дополнительные факультеты имеют модель и доступ, но их расписания/студенты не импортированы в демку.

Экспорт реализован в CSV (Excel открывает UTF-8 с BOM) и PDF; отдельный XLSX не создаётся. SMTP, оценки, оплата, распознавание лиц, геолокация и Moodle отсутствуют. Писем и алертов на `@test.com` приложение не отправляет.
