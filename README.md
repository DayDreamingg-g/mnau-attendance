# MNAU Attendance · Computer Science beta

Текущий проект сохранён на Next.js / React / Prisma / PostgreSQL. Инструкция запуска: [Windows и Docker](docs/WINDOWS.md). Полный список beta-аккаунтов: [CS-BETA-ACCOUNTS.md](docs/CS-BETA-ACCOUNTS.md).

## Подготовка данных

Источники beta находятся в `source-data/cs-beta/`: четыре исходных PDF и DOCX, извлечённые таблицы, имена студентов, страницы, координаты ячеек, исходный текст и SHA-256. Из расписаний использованы только ячейки, покрывающие колонки КН. Соседние колонки не являются источником преподавателя. Общая ячейка КН 3/1 + КН 3/2 создаёт одну Lesson с двумя LessonGroup.

| Группа | Реальных студентов после первой подготовки |
|---|---:|
| КН 1/1 | 17 |
| КН 2/1 | 0 |
| КН 3/1 | 20 |
| КН 3/2 | 21 |
| КН 4/1 | 0 |

ФИО сохранены без исправления написания; исходное значение — в Student.source.rawName. Документ логически называется `Списки груп(1).docx`; фактическое имя приложенного файла сохранено отдельно. Номера страниц взяты из сохранённых разрывов страниц DOCX. Обычные Student не получают User автоматически.

`db:seed` добавляет справочники и демонстрационный контекст других направлений; он не очищает базу и после beta preparation не возвращает synthetic студентов КН. Отдельная **destructive** команда `beta:prepare-cs` удаляет только synthetic студентов пяти КН-групп и их demo-зависимости. Lesson, LessonGroup, справочники, реальные студенты, другие группы и n8n не удаляются. Повторная подготовка сохраняет ручные изменения, переводы, архивирование и настройки аккаунтов. `APP_ENV=demo`, `DEMO_MODE=true` и имя БД `mnau_attendance` обязательны; production заблокирован.

Импорт не создаёт посещаемость и прошлые roster для студентов с неизвестной историей зачисления. `demo:attendance` — отдельная явная команда, создающая недостающие демонстрационные отметки только synthetic студентам. Изолированные тесты используют отдельные fixtures и не обращаются к рабочей БД.

## Календарь

До генерации выводится и сохраняется подтверждённая база:

- 14–20.09.2026 — LOWER / DENOMINATOR;
- 21–27.09.2026 — UPPER / NUMERATOR;
- далее чередование относительно 14 сентября, без ISO odd/even;
- целая ячейка — EVERY_WEEK.

`schedule:generate` создаёт календарь КН из 76 исходных ячеек. По умолчанию диапазон 01.09.2026–31.01.2027; можно передать `--from=YYYY-MM-DD --to=YYYY-MM-DD`. Одновременно обе половины split-cell не назначаются. Старые будущие synthetic занятия, относящиеся только к КН, отменяются с аудитом; строки и история остаются. Старые CS-only demo/schedule записи скрыты из основного beta-календаря, их журналы доступны только для чтения по сохранённой ссылке. Повторный запуск не дублирует Lesson. `--replace` запрещён, так как удалял историю.

Для прежнего демонстрационного календаря остальных направлений сохранена отдельная `schedule:generate-faculty`. Она исключает КН, сохраняет существующие занятия и использует прежние source-data. Неуточнённые split-cell других направлений остаются демонстрационными; эта команда не нужна для beta КН.

Пархоменко А.Ю. и О.Ю. объединены в **доц. Пархоменко О.Ю.**, Богатенкова/Богатєнкова — в **ст.в. Богатєнкова О.Є.** по подтверждению пользователя. В каждом источнике сохранено исходное написание. «Вакансія» не создаёт Teacher/User. Получено 19 преподавателей; email определяется транслитерацией фамилии и инициалов с устойчивым суффиксом при коллизии.

## Роли, журналы и состав групп

StarostaAssignment связывает User с Group независимо от Student. Пять технических старост не притворяются конкретными студентами. Общий куратор выбирает курс → группу; выбор отражён в URL. Главная beta-страница декана/администратора сфокусирована на КН, с переходом ко всему факультету.

Староста своей группы и куратор управляют ФИО, необязательным телефоном и архивом. Перевод требует прав куратора/декана/ADMIN/DEVELOPER на обе группы. Добавление и восстановление заполняют текущий и будущие roster, не создавая прошлых пропусков. При переводе LessonStudent.groupId сохраняет прежнюю группу для истории и отчётов; будущие roster изменяются транзакционно. Все изменения сохраняют actor, время, группу, студента, старые/новые значения и reason/source в AuditLog.

Создание Student account — отдельное действие CURATOR/DEAN_OFFICE/ADMIN/DEVELOPER. Случайный пароль показывается один раз. Телефон доступен самому студенту и уполномоченным управляющим группой; Teacher его не получает. Публичный login не содержит реальные данные и учётные данные.

Teacher видит свои занятия. До начала пары запись запрещена сервером; в текущий день Europe/Kyiv разрешены PRESENT/N/HV/unmarked. Староста сохраняет только draft; Teacher подтверждает либо меняет его. Подтверждённую строку староста не перезаписывает. После окончания дня исправления доступны назначенным CURATOR/DEAN_OFFICE/ADMIN/DEVELOPER с обязательной причиной. Используются транзакция, optimistic locking, requestId и атомарный аудит.

DEVELOPER имеет права управления как ADMIN. Администрирование включает поиск, роли, назначения Teacher/Starosta/Curator, enable/disable, случайный reset и beta reset только в demo. Изменение пароля/disable отзывает сессии. Хеши, session hashes и machine token не попадают в UI или audit snapshots.

Часы beta по умолчанию реальные Europe/Kyiv. В UI только компактный DEMO. `beta:realtime` очищает DEMO_DATE в существующих env, сохраняя остальные настройки. Фиксированная дата остаётся явной функцией developer testing; сессии и rate limit всегда используют реальные часы.

## Метрики, отчёты и интеграции

`PRESENT / (PRESENT + N) × 100`; HV исключён из знаменателя. Нулевой знаменатель означает «Немає даних». Пороги <70% и <50% применяются до округления. Draft/unmarked учитываются в полноте, не превращаются в пропуски. Считаются завершённые неотменённые занятия; агрегаты суммируют исходные отметки. После перевода один студент может присутствовать в отчёте нескольких групп за период — каждая строка содержит историю своей группы.

Сохранены PDF/CSV, фильтры, dark/light theme, session authentication, серверные scopes и шесть workflows n8n. Описание n8n: [n8n/README.md](n8n/README.md). Базы приложения и n8n разделены; подготовка beta не меняет n8n.

## Проверки и ограничения

`npm.cmd ci`, `db:generate`, `typecheck`, `lint`, `test`, `build`, `test:integration`. Integration запускается после build и использует временную PostgreSQL WASM БД на портах 5543/3001. Рабочий DATABASE_URL не используется. Beta suite отдельно: `test:beta`.

- У ст.в. Болотських в ячейке КН нет инициалов; они не выдуманы. Аккаунт создан по фамилии.
- Для некоторых корпусов PDF даёт только сокращение; адрес не выдуман.
- Источники не задают праздники, каникулы и изменения дат; календарь повторяет недельную сетку в выбранном диапазоне.
- Исходный DOCX проверен по XML и сохранённой пагинации; bundled LibreOffice в среде отсутствует, повторный Word render недоступен.
- Docker build был вызван, но локальный Docker Engine недоступен. Успех PGlite-тестов не заменяет проверку настоящего PostgreSQL-контейнера. Данные рабочей БД будут подготовлены при выполнении команд из Windows-инструкции после запуска Docker.
