# Автоматизация отчётности MNAU Attendance

Сайт самостоятельно сохраняет журналы, считает аналитику и формирует файлы. n8n вызывает защищённый машинный API. Остановка n8n не отключает журнал, авторизацию или ручные отчёты.

## Workflow exports

Все шесть JSON можно импортировать через меню **Import from File**. Они сохранены неактивными, без токенов и credential IDs. У HTTP Request указано только имя credential `MNAU report machine`.

| Файл | Назначение | Europe/Kyiv | Область и период по умолчанию |
| --- | --- | --- | --- |
| `daily-attendance.json` | Daily attendance summary | Ежедневно 21:00 | Назначенный факультет, текущий день |
| `weekly-curator-summary.json` | Weekly curator summary | Понедельник 08:00 | Предыдущая календарная неделя; только группы с действующим назначением активного пользователя с ролью CURATOR |
| `attendance-alert70.json` | Attention below 70% | Ежедневно 21:10 | От today−28 дней до today включительно; показатель строго ниже70% |
| `attendance-alert50.json` | Critical below 50% | Ежедневно 21:15 | Тот же период; показатель строго ниже50% |
| `monthly-attendance.json` | Monthly attestation | 1-го числа 07:00 | Предыдущий календарный месяц |
| `report-generation.json` | Manual PDF/CSV orchestration | Только Manual Trigger | Ручной запуск месячного отчёта; тело HTTP node можно настроить |

Каждый workflow имеет Manual Trigger. Расписание n8n использует настоящие системные часы. При явно включённом demo clock отчётный период вычисляет сайт относительно demo-даты; системные часы n8n не меняются. Для демонстрации используйте Manual Trigger и при необходимости явные `from`/`to`.

Алерты сохраняются в приложении: summary, выбранные студенты, PDF, CSV и устойчивый `alertKey`. Поле `delivery: "STORED_ONLY"` явно показывает отсутствие отправки. Эти workflow не отправляют email/Slack или другие сообщения. Порог70% включает критических ниже50%; HV исключён из знаменателя, черновики и отсутствующие отметки показаны отдельно, процент считается до округления.

## Подключение в Docker Compose

1. Запустите приложение, миграции и seed по основному README. Откройте [локальный n8n](http://localhost:5678) или порт `N8N_PORT` из вашего `.env.compose` и создайте owner account. Он независим от аккаунтов сайта.
2. Импортируйте все шесть JSON из этой папки.
3. В **Credentials → Header Auth** создайте `MNAU report machine`: Header Name `Authorization`, Header Value `Bearer ` + значение `REPORT_MACHINE_TOKEN` из игнорируемого `.env.compose`.
4. В HTTP node **Create and persist report** каждого workflow выберите этот credential. Имя в экспорте служит подсказкой; назначение существующего credential проверьте после импорта. В JSON токен не вставляйте.
5. URL в Compose уже настроен: `http://web:3000/api/machine/reports`. Нажмите **Execute Workflow**. Финальный node **Verify persisted result** должен вернуть `state: "READY"`. Повтор должен вернуть `reused: true`, если данные не изменились.
6. На сайте войдите как admin/dean → «Звіти» → откройте сводку, затем PDF/CSV. После ручной проверки активируйте нужные расписания в n8n.

Токен привязан только к `REPORT_FACULTY_SLUG` (по умолчанию `management`). Он не даёт доступа к login, attendance, admin API или браузерным скачиваниям. Переданная чужая `faculty` отклоняется; сервер проверяет принадлежность specialty/group/student разрешённому факультету.

## Тело машинного запроса

```json
{"kind":"WEEKLY","from":"2026-08-31","to":"2026-09-06","requireReady":true}
```

Поддерживаются `kind`: `DAILY`, `WEEKLY`, `MONTHLY`; необязательные `from`, `to`, `course`, `specialty`, `group`, `student`, `threshold` (50/70). Даты ограничены периодом до366 дней. Выбор студента пересчитывает raw counts только для него.

Действия автоматизации:

```json
{"action":"WEEKLY_CURATORS","requireReady":true}
```

```json
{"action":"ALERT70","requireReady":true}
```

```json
{"action":"ALERT50","requireReady":true}
```

`WEEKLY_CURATORS` создаёт один отчёт на каждую реально назначенную группу. В результате выполнения несколько кураторов одной группы перечислены рядом с одной ссылкой на сохранённый отчёт; имена действующих кураторов сохраняются в summary. Просмотр и скачивание сохраняют существующие права ADMIN/DEAN_OFFICE. Отправки этим людям нет. Отсутствие действующих назначений возвращает READY с пустым списком и понятным сообщением.

## Дедупликация, повторные попытки и ошибки

- Уникальный ключ включает вид, период и область, в том числе выбранного студента/порог. Один период и область обновляют ту же запись Report.
- Fingerprint включает экспортируемые значения, названия и действующие назначения кураторов. Изменение отметок или имени обновляет файлы; неизменённый повтор повторно использует готовый результат.
- PENDING lease блокирует параллельное создание. После пяти минут незавершённую генерацию можно повторить. Сбой создания PDF/CSV сохраняется как FAILED с периодом, областью и сообщением об ошибке.
- Все HTTP nodes делают до3 попыток через5 секунд с timeout120 секунд. `requireReady: true` превращает активный PENDING в HTTP503 с `Retry-After: 5`, чтобы повтор заново проверил сохранённый результат. Без него API сохраняет обычное поведение202/PENDING.
- Final Code node отвергает любой результат, отличный от READY. n8n сохраняет неуспешные executions и прогресс; в execution видны node, HTTP status и безопасный текст ошибки. Машинный API логирует действие и статус без body/headers/credentials.
- При недоступном сайте ошибка остаётся в failed execution n8n: невозможно записать Report в недоступную базу сайта. Повторите workflow после восстановления. После исчерпания retries workflow остаётся ошибочным, успешный отчёт не имитируется.

## Проверка

`npm.cmd test` проверяет контракт всех шести exports: структуру, отсутствие секретов, credential name, retries, часовой пояс и обработку READY/PENDING. Серверные integration tests проверяют назначенных кураторов, пороги, scope, дедупликацию и retriable503.

`scripts/verify-n8n.mjs` может импортировать все шесть workflows и выполнить каждый дважды через настоящий локально установленный n8n CLI, если задан `N8N_TEST_BIN`. Временный Header Auth передаётся CLI через анонимный memory file на Linux, отдельно от репозитория. Этот скрипт требует работающий тестовый API и собственную временную БД n8n; не направляйте его на рабочую базу. Наличие скрипта не означает, что проверка уже выполнена в текущей среде.

Проверка независимости на Windows:

```powershell
docker compose --env-file .env.compose stop n8n
```

Сохраните разрешённую отметку в журнале и проверьте её после F5. Затем:

```powershell
docker compose --env-file .env.compose up -d n8n
docker compose --env-file .env.compose logs --tail 100 n8n
```

Credentials n8n шифруются его `N8N_ENCRYPTION_KEY` в отдельной БД. Не экспортируйте decrypted credentials, не добавляйте `.env`/`.env.compose` в Git и не копируйте токен в `NEXT_PUBLIC_*`. Сохраняйте ключ шифрования вместе с собственной резервной копией.
