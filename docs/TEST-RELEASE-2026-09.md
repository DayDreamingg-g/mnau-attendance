3. Фильтр предмета терялся при разборе запроса/preview; часть ролей, включая преподавателя, не имела Reports scope. Теперь предмет, семестр, вся область факультета и доступные группы проходят до снимка и файлов. Приёмка также выявила и исправила подстановку КН при явно выбранном другом факультете.
4. Старый расчёт исключал неподтверждённые сохранённые статусы. Теперь общие отметки входят в аналитику сразу, по формуле P/(P+N). HV и невідмічені не входят в знаменатель; при нуле — «Немає даних».
5. Отчёт строится из согласованного снимка в транзакции RepeatableRead. Учитывается историческая группа LessonStudent; перевод не теряет прошлую выборку. Порог для одного студента считается из суммы отметок его групп. Готовые снимки и PDF/CSV/XLSX находятся в PostgreSQL. Создание, просмотр и прямое скачивание проверяют актуальный scope.

Ошибки 422 (пустая выборка), 401/403/404 (доступ) и ошибки формирования различаются. Ошибке сервера выдаётся безопасный идентификатор; контекст содержит этап/объект/период и тип ошибки, без SQL-параметров, токенов или строк подключения. n8n не участвует в ручном сохранении журнала и генерации отчёта.

## Реализованное

- Общий журнал преподавателя/старосты, собственная группа старосты, текущий день Europe/Kyiv, поздние исправления с причиной, транзакция/аудит/requestId/версия. При конфликте локальные изменения остаются в форме для сверки.
- Отчёты на сайте, PDF, CSV и XLSX: занятие × группа, итоговые статусы, состав, преподаватель, предмет, время, onlineUrl, незавершённые журналы. Уникальные люди отличаются от student × lesson.
- Профиль с ПІБ, должностью и сеансами; обязательная смена пароля через серверную защиту, включая минимальный экран старосты и выход до смены. Миграция не меняет хеши, требование устанавливается только один раз.
- Административный случайный reset показывает временный пароль один раз, требует следующую смену и отзывает сеансы. Старый общий reset запрещён. Собственная смена проверяет текущий пароль и отзывает другие устройства.
- Cooldown PostgreSQL: по источнику + нормализованному email, 5 ошибок, затем 1/2/4/8/16/32/60 минут; отдельный IP-порог 100 за 15 минут для NAT. `LOGIN_FAILURE_THRESHOLD` (3–20) и `LOGIN_IP_THRESHOLD` (30–1000) настраиваются без внешнего сервиса. Повтор в cooldown не продлевает его; успешный вход сбрасывает парный счётчик. Административный сброс требует причины.
- В известном Railway service с точным APP_ORIGIN используется ingress `X-Real-IP`; вне него произвольные forwarded-заголовки игнорируются (локально общий network bucket). Сессия не привязана к IP. При удалённой приёмке нужно подтвердить фактическое поведение proxy, поскольку локальные запросы не доказывают конфигурацию Railway. Спецификация: https://docs.railway.com/networking/public-networking/specs-and-limits.
- Мастер преподавателя, связи предметов/групп, несколько ролей/workspace; Teacher.id и исходное написание сохраняются. Архивирование Teacher сохраняет Lesson/Attendance и другие роли, показывает будущие назначения. Они не отменяются и не переназначаются случайно. Собственные роли — отдельная подтверждённая операция DEVELOPER, последний административный доступ защищён.
- Feedback для действующих пользователей, административный inbox, общий аудит с фильтрами и страницами; dean directory в scope факультета; статус системы с отдельными счётчиками КН/всей БД. Для n8n честно показано отсутствие health-проверки.
- Активная навигация light/dark и aria-current, TEST рядом с eyebrow, валидируемые http/https onlineUrl, авторизованные исходники. DOCX хранится в БД, PDF включены в Docker runtime; глобальный персональный DOCX преподавателю не выдаётся.
- AcademicTerm, выбор истории, подтверждение нового состава, DB triggers на уроки/группы/состав/отметки/отправки архива. Повторного открытия архива нет. Январские занятия сохранены вне подтверждённого осеннего семестра.

## Railway: подготовленные команды, ещё не применено

Авторизованного подключения к фактическим настройкам/БД Railway в этой работе нет. Перед применением проверить в **существующем сервисе** `mnau-attendance`: DATABASE_URL указывает на его Postgres с БД `railway`, `BETA_DATABASE_NAME=railway`, `APP_ENV=demo`, `DEMO_MODE=true`, `DEMO_DATE` отсутствует/пустая, `APP_ORIGIN=https://mnau-attendance.up.railway.app`, `COOKIE_SECURE=true`, service ID доступен автоматически. Сервер слушает `0.0.0.0:8080`, домен направлен на 8080. Секретные значения не копировать в логи. Не пересоздавать Postgres.

### Обычный Pre-deploy

```sh
npm run db:migrate
```

### Одноразово: сначала миграция и dry-run импорта

В существующем авторизованном service shell с tools/dependencies этой версии:

```sh
sh -c 'npm run db:migrate && npm run beta:import-complete-cs-roster -- --dry-run'
```

После сверки плана ожидаются прежние 58, новые 70 и сохранённые законные дополнительные записи. На ещё не импортированной базе dry-run backfill закономерно потребует сначала все 128 provenance-строк.

### Одноразовый полный Pre-deploy

Если команды выполняются временным Pre-deploy, использовать **всю** последовательность, которая останавливается при первой ошибке:

```sh
sh -c 'npm run db:migrate && npm run beta:import-complete-cs-roster -- --dry-run && npm run beta:import-complete-cs-roster -- --apply && npm run beta:backfill-cs-history -- --dry-run && npm run beta:backfill-cs-history -- --apply && npm run beta:verify-cs'
```

После одного успешного применения вернуть обычный Pre-deploy `npm run db:migrate`. Импорт/backfill не добавлять в каждое начало web. Read-only проверку можно повторять отдельно: `npm run beta:verify-cs`. Успешный build/Online не доказывает импорт. Нужны JSON-результаты из нужной Railway БД и ручная проверка web.

### Start Command

Сохранить существующий Railway Start Command с `.next/standalone/server.js`, копированием public/static и портом 8080. Эквивалент полной команды для текущей standalone-структуры, если поле нужно восстановить из этой инструкции:

```sh
sh -c 'mkdir -p .next/standalone/public .next/standalone/.next/static && cp -R public/. .next/standalone/public/ && cp -R .next/static/. .next/standalone/.next/static/ && HOSTNAME=0.0.0.0 PORT=8080 node .next/standalone/server.js'
```

Эта команда относится к существующему Railway standalone-развёртыванию. Она не заменяет default CMD плоского локального Compose web image. Pre-deploy и Start — разные поля. Не заменять Railway запуск на `node server.js` и не переносить туда локальный порт 3000.
